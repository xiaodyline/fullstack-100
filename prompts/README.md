# 学习提示词

以下提示词可以独立使用，也可以组成「学习—关联—测试」的循环。将花括号中的占位内容替换为当前学习主题即可。

## 1. 单个关键词深度学习

```text
请深入讲解「{关键词}」。

按照以下结构展开：

1. 问题背景：它要解决什么问题？为什么会出现？
2. 核心原理：它的工作机制是什么？关键过程如何运行？
3. 实际应用：在哪些工程场景中使用？结合具体案例说明。
4. 实现方式：必要时提供代码、伪代码或架构示意，解释关键步骤。
5. 设计权衡：它有哪些优点、局限和适用边界？与常见替代方案有什么区别？
6. 知识关联：学习它之前需要理解什么？它又是哪些技术的基础？
7. 理解检查：最后给出一道能够检验原理理解和实际应用能力的问题，等待我回答后再点评。

讲解要求：
- 从问题和原理出发，不要堆砌术语。
- 先讲通用机制，再用具体技术或语言举例。
- 区分通用原理、具体实现和版本相关行为。
- 根据主题控制深度，避免为了完整而引入无关内容。
- 对容易混淆的概念明确比较。
```

## 2. 跨知识点关联分析

```text
请分析「{概念 A}」与「{概念 B}」之间的关系。

重点回答：

1. 两者分别解决什么问题，处于系统的哪个层次？
2. 它们的核心原理和工作过程有什么异同？
3. 两者之间存在什么依赖、协作或替代关系？
4. 在真实系统中，它们如何共同工作？请用一个完整场景串联说明。
5. 在什么情况下应该选择其中之一，或同时使用？
6. 它们与其他相关概念还形成了怎样的知识联系？

最后用一张简洁的对比表总结，并给出一个综合场景题，检验我能否根据实际问题判断两者的关系。

不要孤立地介绍两个概念，重点解释它们在完整技术体系中的位置、边界和相互作用。
```

## 3. 知识掌握程度测试

```text
请根据我已经学习的关键词「{关键词或知识模块}」，进行一次阶段性掌握测试。

测试分为三个层次：

1. 基础理解：检验概念定义、核心原理和关键机制。
2. 原理分析：给出运行过程、代码片段或技术现象，让我分析原因。
3. 工程应用：给出真实的软件开发或系统设计场景，让我判断方案并说明理由。

测试规则：
- 每次只提出一道题，等待我回答。
- 不提前透露答案或提示关键结论。
- 我回答后，指出正确之处、错误之处和遗漏的关键点，再给出参考答案。
- 根据我的表现动态调整后续题目的难度。
- 如果发现基础概念存在缺口，先针对缺口补充讲解，再继续测试。
- 记录各关键词的掌握情况：理解充分、需要巩固、尚未掌握。

完成一轮后，给出知识掌握总结，指出最值得补强的知识点，以及下一步适合学习的内容。
```

## 推荐使用顺序

1. 先阅读 [知识地图](../docs/knowledge-map.md)，确定关键词和知识依赖关系。
2. 使用提示词 1，每次学习 3～5 个关键词。
3. 遇到关联概念时使用提示词 2，建立体系化理解。
4. 完成一个知识模块后使用提示词 3，检查掌握程度并安排复习。
