# 全栈开发 100 个核心关键词知识地图

这份知识地图以现代软件工程师的完整能力体系为目标，覆盖计算机基础、编程语言、数据结构与算法、操作系统与网络、前端、后端、数据库、软件工程、系统架构和 AI Agent。

采用 **10 个知识模块 × 每个模块 10 个关键词** 的组织方式。模块数量相同只是为了便于浏览，不代表各领域的重要程度相同。筛选遵循基础优先、工程导向和知识关联三个原则。

**优先级说明：** P0 表示必须深入理解的核心基础；P1 表示应熟练掌握并能用于项目；P2 表示理解原理、适用场景和技术边界即可。

## 四、关键词之间的知识依赖关系

如果把 100 个知识点看成一张地图，它们并不是相互独立的。

### 知识分层

1. **计算机基础**：计算机组成、数据表示、内存、算法复杂度。决定数据如何存储、计算和访问。

2. **程序设计与执行**：类型系统、内存管理、编程范式、并发、异步。决定程序如何组织和执行。

3. **系统运行与通信**：操作系统、进程线程、TCP/IP、HTTP、DNS。决定程序如何运行，以及如何与外部系统通信。

4. **软件开发与数据管理**：前端、后端、数据库与缓存。将基础原理转化为实际业务能力。

5. **系统架构与工程质量**：分布式系统、消息队列、高可用、容器化、CI/CD、可观测性。解决系统规模扩大后的可靠性、性能和维护问题。

6. **AI 工程**：LLM、Embedding、RAG、Tool Calling、Agent、Multi-Agent、Evaluation。将模型能力转化为可运行、可控制、可评估的软件系统。

这是便于学习的逻辑分层，不是严格的单向依赖图。例如，数据库、网络、操作系统和软件工程之间存在大量交叉依赖。

### 值得重点理解的关联链

| 起点 | 关联链 | 最终解决的问题 |
|---|---|---|
| 内存管理 | 内存 → GC → 闭包 → 内存泄漏 | 为什么程序会出现内存占用持续增长 |
| 异步编程 | Promise → Event Loop → 并发控制 → 任务队列 | 如何处理大量异步任务 |
| 网络通信 | DNS → TCP → TLS → HTTP → SSE | 一次 Web 请求如何完成 |
| 数据访问 | SQL → 索引 → 执行计划 → 缓存 | 如何优化慢接口 |
| 业务可靠性 | API → 幂等性 → 事务 → 消息队列 | 如何防止重复提交和数据不一致 |
| 系统架构 | 单体 → 服务拆分 → RPC → 负载均衡 → 容错 | 如何构建可扩展系统 |
| AI 应用 | LLM → Prompt → RAG → Tool Calling → Agent → Evaluation | 如何构建可靠的 AI 应用 |

这些关联链比单纯记住每个概念更有价值。

## 五、建议的学习顺序

虽然知识地图分为 10 个模块，但实际学习不一定严格按照模块编号推进。建议拆成五个阶段：

| 阶段 | 学习范围 | 目标 |
|---|---|---|
| 第一阶段 | 模块 1、2、3 | 建立计算机和编程基础 |
| 第二阶段 | 模块 4、5 | 理解操作系统、网络和浏览器 |
| 第三阶段 | 模块 6、7 | 掌握前后端与数据管理 |
| 第四阶段 | 模块 8、9 | 建立软件工程和系统架构能力 |
| 第五阶段 | 模块 10 | 建立 AI 应用和 Agent 工程能力 |

P2 可以作为拓展学习内容，主要包括 CPU 指令执行细节、缓存局部性、复杂图算法、操作系统调度、分布式共识、分布式事务和多 Agent 协作等。它们不需要在基础阶段全部深入掌握。

### 每个知识点的学习标准

- **理解**：能够解释它是什么、解决什么问题。

- **掌握**：能够讲清底层原理，分析运行过程。

- **应用**：能够在真实工程中使用，并做出合理的技术选择。

不是所有关键词都要求达到第三层。例如，分布式共识需要理解原理和适用场景，但不一定要求独立实现共识算法。

## 六、学习方法与执行建议

每次学习 3～5 个关键词，形成一个循环：

1. **理解概念**：它是什么？解决什么问题？

2. **理解原理**：它是如何工作的？为什么这样设计？

3. **工程实践**：在真实项目中如何使用？有哪些替代方案？

4. **关联学习**：它和之前学过的知识有什么联系？

5. **主动测试**：通过实际问题检验是否真正理解。

### 第一批建议学习内容

1. 计算机组成原理

2. 二进制与数据表示

3. 内存层次结构

4. 时间与空间复杂度

5. 并发与并行

这五个概念能够为后续学习编程语言、操作系统、网络和性能优化提供基础。

学习重点是逐渐形成一套能够解释真实软件系统的知识体系，而不是单纯追求学习速度。
